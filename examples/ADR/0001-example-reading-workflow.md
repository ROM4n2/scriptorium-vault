# ADR-0001（示例）: 阅读笔记先落 Inbox 再晋级

> **演示目标**：展示决策如何留痕。本文是中立领域（阅读）的虚构决策，替换成你的领域即可。模板见 `Templates/tpl-adr.md`。

## 1. 上下文与问题

读书笔记常有两种写法：读完直接写进正式区（快），或先进 `99-Inbox/` 再经流转晋级（慢一步）。

- 直接写正式区的问题：位置判断依赖当下理解，读完后常有更好的归属；写错位置会污染正式区结构，且**读者（未来的自己）无法区分「已整理」与「随手记」**。
- 先进 Inbox 的问题：多一步操作，短期看起来是摩擦。

约束：单人使用、无外部协作、每周阅读 1–2 本。

## 2. 决策驱动因素

1. 正式区必须保持可信（作为长期查阅的真值源）；
2. 单次操作成本不能高到让人放弃记笔记；
3. 归属判断应该发生在理解更充分之后；
4. 结构必须可被自动化工具（质量门、流转器）校验。

## 3. 备选方案

**A. 直写正式区**：零额外步骤，但结构可信度受损，且质量门无法区分草稿与成品。

**B. 全部进 Inbox 后统一晋级**（采纳）：多一步流转，但归属判断发生在读完之后，正式区始终保持「已整理」语义。

**C. 双轨并行**（重要笔记直写、其余进 Inbox）：需要人每次判断「重要与否」，判断成本最高，且规则不可执行。

## 4. 决策结论

采纳 **B**。理由：把「归属判断」推迟到理解充分时，同时让正式区获得一个可校验的语义——正式区任何一篇都经过流转，因此质量门可以对其施加更严格的约束（frontmatter、链接、双版本对齐）。

代价：每次记笔记多一步；缓解方式是让流转变成一条命令（`vault-inbox-consolidate --apply`）而非人工搬运。

## 5. 后果与状态

- **好处**：正式区可信；草稿有 TTL（7 天）迫使清理；质量门可自动化。
- **代价**：需要记得跑流转；`99-Inbox/` 会短期堆积（由体检报告提示）。
- **状态**：stable（示例；替换为你的真实决策后改为实际状态）。
